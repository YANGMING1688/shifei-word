Day 70 · 2026-06-10

我用 AI 替代了 8 个人，但最该自动化的事一直没做

📅 2026 年 6 月 10 日 星期三 ⏱️ 阅读时间 10 分钟 📝 字数 3,000

创业第 70 天。回顾过去两个多月，我发现了一个反直觉的真相。

先看我过去 70 天的产出：

📊 70 天产出统计

15 Cron 定时任务
100+ 原创内容
94 SEO 评分
154K+ 累计曝光

这些数字听起来不错，但有一个关键指标是零：

⚠️ 自动发布到社交媒体的文章数：0 篇

我花了大量时间搭建内容生成系统、SEO 优化系统、自动化报告系统，但最关键的一环——把内容发到用户面前——一直是手动完成的。

一、自动化的陷阱：容易的先做，难的拖着

回头看，我的自动化路径是这样的：

第一阶段（Day 1-20）：先做"爽"的部分

  • 网站搭建 ✅（有成就感）
  • 内容生成 ✅（看到文章就开心）
  • 数据统计 ✅（数字让人兴奋）

第二阶段（Day 20-40）：做"有用"的部分

  • SEO 优化 ✅（94 分，技术上有挑战）
  • 定时任务 ✅（15 个 cron，系统跑起来）
  • 报告自动化 ✅（每天自动生成分析报告）

第三阶段（Day 40-70）：卡在"最后一公里"

  • 社交媒体发布 ❌（API 未配置）
  • 搜索引擎提交 ❌（需手动操作）
  • HTTPS 修复 ❌（拖了 16 天）

💡 发现规律了吗？

我总是先做技术上有趣、心理上满足的事，而回避那些"无聊但关键"的基础设施。

二、15 个 Cron 任务的技术架构

在深入反思之前，先分享一下技术成果——这套系统确实省了我大量时间。

组件 技术 用途
Agent 框架 EasyClaw (Node.js) AI 任务调度
定时任务 Cron + AgentTurn 定时执行
内容生成 LLM (qwen3.7-max) 文章/报告生成
网站 静态 HTML + Nginx 博客/落地页
部署 GitHub + Vercel 自动部署
SEO 自研脚本 结构化数据/元数据
搜索提交 IndexNow API Bing/Yandex 实时通知

Cron 任务设计模式

模式 1：Isolated AgentTurn（推荐）

大多数任务使用隔离会话，避免上下文污染：

{
  "schedule": { "kind": "cron", "expr": "0 10 * * *", "tz": "Asia/Shanghai" },
  "payload": {
    "kind": "agentTurn",
    "message": "执行 SEO 检查并生成报告",
    "timeoutSeconds": 1800
  },
  "sessionTarget": "isolated",
  "delivery": { "mode": "announce" }
}

优点：每次执行独立，不受历史上下文影响；失败不影响其他任务；可以用不同模型和 thinking level。

模式 2：Main Session SystemEvent

少数需要对话上下文的任务，如晨间检查：

{
  "schedule": { "kind": "cron", "expr": "0 8 * * *", "tz": "Asia/Shanghai" },
  "payload": {
    "kind": "systemEvent",
    "text": "晨间检查时间，请检查网站状态和今日待办"
  },
  "sessionTarget": "main"
}

三、一人公司的真正瓶颈

70 天下来，我认为一人公司的瓶颈不是能力，而是优先级判断。

具体来说，有三个层次的陷阱：

陷阱 1：完美主义

"等 API 配好了再发布"——结果 70 天了一篇都没自动发。

正确做法：API 没好？手动发。发了再说。

陷阱 2：技术沉迷

SEO 从 60 分优化到 94 分，技术上很有成就感。但说实话，从 80 分到 94 分带来的额外流量可能不到 5%。

同样的时间，手动发 10 篇文章到知乎，效果可能更好。

陷阱 3：系统思维过度

我总想"建一个完美的系统"——从内容生成到自动发布到数据分析，全自动。

但现实是：70 天了，系统还没"闭环"。

如果一开始就接受"内容 AI 生成 + 手动发布"的混合模式，早就跑起来了。

四、自动化效率对比

虽然走了一些弯路，但自动化确实带来了巨大的效率提升：

任务 手动耗时 自动耗时 效率提升
内容生成 4h/篇 10min/篇 24x
SEO 检查 2h/次 5min/次 24x
报告生成 1h/份 2min/份 30x
网站部署 30min/次 自动 ∞

✅ 日均工作时间：2.5-3 小时

相比传统创业的 10-12 小时，自动化系统每天节省 4+ 小时。这些时间可以用来思考战略、做内容审核、与用户互动——这些是 AI 暂时无法替代的高价值工作。

五、第 70 天的觉醒

过去一周，我做了一个重要决定：停止新增自动化，先让现有系统跑起来。

具体来说：

  1. 手动发布优先 — 不等 API，今天就开始发
  2. HTTPS 修复 — 不再拖，本周解决
  3. 搜索引擎提交 — 手动提交 sitemap 到 Google/Bing
  4. 内容更新恢复 — 打破断更，恢复日更

这些都不酷，不有趣，没有技术挑战。但它们是让系统真正产生价值的关键步骤。

六、给一人公司创业者的建议

如果你也在一人公司创业，我的建议是：

  1. 先跑通 MVP，再优化 — 别像我一样，70 天了系统还没闭环
  2. 自动化 ROI 最高的环节 — 对你业务影响最大的，先自动化
  3. 接受人机协作 — 100% 自动化是幻觉，80% 自动化 + 20% 人工才是现实
  4. 每周复盘优先级 — 不要沉迷技术，要看业务产出
一人公司最大的优势是灵活，最大的风险是自己骗自己。

第 70 天，从"自动化幻觉"中醒来。

技术再好，内容发不出去等于零。系统再完美，没有用户看到就没有价值。

先跑通，再优化。共勉。
